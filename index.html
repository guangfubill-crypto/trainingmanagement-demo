A2. 启动后端：终端一

确认当前在 training-reference 根目录。以下初始安装命令首次运行一次；两个终端不要互相替代。

cd backend
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
./.venv/Scripts/python.exe -m app.cli init-admin --username admin
./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

创建管理员时按提示输入自己的密码（至少 8 位）。终端输入密码通常不显示字符，不是卡住。不要使用别人的密码文件。已初始化过就跳过 init-admin，不要删除数据库来重置账号。

最后一条命令会持续运行。保持终端打开，在浏览器访问 http://127.0.0.1:8000/api/health，检查 status 和 database 为 ok。若未启动成功，先看终端第一条错误。

A3. 启动前端：终端二

新开终端，在文件管理器进入 training-reference 根目录后“在终端中打开”，执行：

cd frontend
npm.cmd ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm.cmd run dev

访问 http://127.0.0.1:5173，用刚才创建的 admin 和自己的密码登录。后端 8000、前端 5173 是两个不同服务，需要同时运行。若 Vite 自动换到 5174，先处理已有 5173 服务，不要悄悄换端口造成可信来源不匹配。

日常再次启动，只需要终端一的 uvicorn 和终端二的 npm.cmd run dev。停止时在对应终端按 Ctrl+C。

故障处理：按现象定位

仓库 404：先确认账号已获读取权限且接受邀请，不是换一条 git 命令就能解决。

python 或 npm 找不到：重新打开终端检查 PATH 和版本；不要继续后续安装。

依赖下载失败：保存失败包名、版本、网络错误，请老师排查包源访问；不要任意升级锁定版本。

端口被占用：确认是不是自己上一轮终端还在运行，只停止已确认属于自己的服务。不要结束不认识的进程。

页面能打开但登录失败：检查后端健康、使用的管理员密码，以及浏览器地址是否仍为 127.0.0.1:5173；错误端口可能触发来源拒绝。

No module named：核对工作目录在 backend，且使用 .venv/Scripts/python.exe；安装到全局 Python 不等于装进虚拟环境。

浏览器测试找不到 Chromium：在 frontend 运行 npx.cmd playwright install chromium，并确认下载成功。

无法打包：保留 desktop/build.ps1 中第一条失败命令输出，核对前端构建、虚拟环境、Electron 下载；不要把 release 中旧包当成本轮新包。

通用求助提示词：我在【工作目录】执行【完整命令】，预期【结果】，实际退出码为【值】，错误是【脱敏后的原文】。请先定位原因，给出最小修复并说明如何复验，不重建项目、不删除数据库、不任意升级依赖。

SPECS · REQUIREMENT / SCENARIO

03

把一句需求写成可检查的规则

Requirement 是“必须遵守的规则”；Scenario 是“在某个具体情况下，应该发生什么”。

3.1 先认识 WHEN / THEN

WHEN 就是“当……发生时”；THEN 就是“系统应当……”。SHALL 表示“必须”，不是“最好能做到”。

需求：管理员可以新增课程。

只有这一句还不够。还要说清：填哪些内容？编号重复怎么办？保存后会不会丢？谁没有权限？

3.2 课程规格的教学拆解

规则具体场景 WHEN预期结果 THEN
有效课程可以保存管理员填写完整资料，编号尚未使用保存成功，获得记录 ID，之后可查到。
编号不能重复再次新增编号 PY-001拒绝保存，原课程不被覆盖。
课时必须为正整数填 0、-1 或 1.5拒绝保存，提示输入不合法。
课程必须持久保存关闭服务后重新启动，再查询原课程仍然存在。
普通用户只有读取权普通用户尝试新增课程拒绝写入，不产生记录。
展开：真实 OpenSpec 写法示例
### Requirement: 课程管理

#### Scenario: 新增并持久保存
- **WHEN** 管理员提交有效课程
- **THEN** 返回 201 和课程 ID，服务重启后仍可查询

这里 201 是接口表示“创建成功”的状态码。规格原文还规定了字段和错误情况，此处只截取一个场景帮助理解。

5.1 三条管理员保护规则

  1. 不能删除当前正在使用的账号，避免把自己删掉。
  2. 不能删除最后一个管理员，否则没人能管理系统。
  3. 不能把最后一个管理员降为普通用户，理由相同。

5.2 密码与会话

会话可以理解为“登录后获得的临时通行证”。默认有效期为 8 小时。退出、重置密码或删除账号后，对应通行证失效；修改角色后，下一次请求就按新角色检查。

示例：用户原来是管理员。另一个管理员把他改成普通用户后，即使旧页面还显示某个操作按钮，后端也应拒绝他的写操作。
